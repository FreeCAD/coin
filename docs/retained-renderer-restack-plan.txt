RETAINED RENDERER PERFORMANCE RESTACK PLAN
==========================================

This plan audits integration/retained-performance-wip at 707784b61.  It is a
read-only plan: no review branches have been created and no published history
has been rewritten.

The current branch contains 63 commits above
stack/render-geometry-resource-reuse at c8ce046c3.  Those commits form a sound
implementation, but their chronological development history is not the best
review history.  Restack by dependency and reviewer concern instead of making
one branch per optimization.

PROPOSED REVIEW LAYERS
======================

Create five review layers above the amended geometry-resource layer.

1. retained-submission-batching
-------------------------------

Purpose: reduce physical GL submissions without changing scene semantics.

Include:

  * shared pick-range reuse;
  * visual instancing foundation;
  * material, indexed, textured, vertex-color, transparent, and lit batches;
  * retained picking, subelement picking, and depth-stack picking batches;
  * selection and subelement-selection batches with bounded amplification;
  * compatible opaque grouping and shared indexed-edge batching.

Keep semantic and pixel tests next to the implementation.  This layer should
make the draw-call reduction reviewable independently of later scene-update
optimizations.

2. retained-incremental-updates
-------------------------------

Purpose: patch stable retained frames when scene fields change.

Include:

  * frame-owned command-path snapshots;
  * isolated transform and material updates;
  * unique and shared geometry-resource regeneration;
  * command dependency indexing;
  * bounded update batches and stable switch visibility;
  * geometry-regeneration batching;
  * stable material-update batches;
  * mutation-scaling and assembly-mutation benchmarks.

This layer owns notification correctness, invalidation policy, and the decision
between patching and rebuilding.

3. retained-cpu-reuse
---------------------

Purpose: reduce retained-frame construction and unchanged-frame CPU work.

Include:

  * move-finalized command storage;
  * streamlined lazy-state and command construction;
  * SbInlineVector and common inline retained collections;
  * geometry-source lookup reuse;
  * instance classification, stable render-plan, lighting-capture,
    selection-plan, and dependency-index reuse;
  * compact retained command paths;
  * construction attribution and forced-rebuild comparisons not already
    folded into the instrumentation layer.

The reusable container belongs here because this is the first layer that needs
it and includes its independent unit test.

4. retained-interaction-performance
-----------------------------------

Purpose: make hover and repeated retained picking reuse stable work.

Include:

  * shared primitive-pick batching;
  * stable pick topology and pick-submission plans;
  * explicit pick-target refresh measurements;
  * asynchronous closest-pick backend readback;
  * the SoRenderManager asynchronous closest-pick API;
  * workload-viewer asynchronous hover;
  * backend and manager hover-latency benchmarks;
  * depth-stack submission diagnostics and depth-stack scaling coverage.

Keep backend request tokens private.  The public API remains scene-oriented
through SoPickedPoint.

5. retained-workload-coverage
-----------------------------

Purpose: complete representative coverage without changing renderer policy.

Include:

  * visibility and structural-edit workloads;
  * assembly transform, material, geometry, selection, subelement-selection,
    and depth-stack curves not already placed with their implementation;
  * benchmark documentation and the API roadmap;
  * the final saved-WIP parity audit.

This layer should contain only shared workload construction, reporting, and
documentation.  Renderer changes discovered while building it must be folded
into one of the four implementation layers below it.

  3. Rebase the current integration tip onto the amended lower layers in a
